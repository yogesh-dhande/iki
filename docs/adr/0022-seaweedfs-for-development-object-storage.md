# 0022. SeaweedFS replaces MinIO as the development S3 stand-in

- Status: Accepted
- Date: 2026-11-09
- Amends: [0005](0005-postgres-only-data-infrastructure.md), [0014](0014-kubernetes-only-deployment.md)

## Context

ADRs 0005 and 0014 named MinIO as the S3-compatible object store for the
kind development cluster and CI. Production uses AWS S3 and is unaffected.

MinIO's open-source edition is no longer viable. It went into maintenance
mode in December 2025, its repository was archived in April 2026, and its
community images were removed from Docker Hub. There are no further releases
or security patches.

The development store has to support what Iki's files feature relies on:
S3 object versioning, presigned URLs, multipart uploads and signature v4
authentication.

## Decision

Use **SeaweedFS** for development and CI, running `weed mini` (master,
volume server, filer and S3 gateway in one process) as a single non-root pod.

- Credentials are random per cluster, generated by `deploy/dev/up.sh`.
- Anonymous access is rejected, and the `iki` bucket is created at startup.
- Anonymous usage telemetry and the admin UI are turned off.
- The image is pinned by digest.

## Consequences

- Positive: Apache-2.0 licensed, actively maintained since 2015, and
  supports versioning, presigned URLs and multipart uploads.
- Positive: one small pod, quick to start in CI.
- Negative: SeaweedFS's S3 behavior is not identical to AWS. Edge cases,
  such as error codes and checksum headers, must still be tested against
  real S3 in the staging account.
- Negative: one more dependency to track for updates.

## Alternatives considered

- **RustFS**: a MinIO-compatible drop-in, but newer and less proven.
- **Garage**: lightweight, but AGPL-3.0 and lacks S3 object versioning.
