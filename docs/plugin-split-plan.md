# Splitting the example LIMS before M1

Phase 1 mapped the `a794df0f` tree for [ADR 0211](adr/0211-lots-inventory-samples-and-requests.md). The split carries forward example LIMS **0.10.0** from `231cd950`, including the private WorkItem and plain deliverable introduced in 0.9.0.

The request family marks a request delivered only after every recorded result is returned and every expected material has a returned result. A deliverable’s immutable `material` identifies the sample, tube or recorded aliquot it covers. The dose-response starter commissions the two compound tubes. Its luciferase stock and ledger-backed sample belong to the service project. The split retains the run-import request checks and the reviewed put-away plan from main.

## Implementation order and verification

1. **Reconcile the two branches.** After approval, confirm the merged work-item/privacy and release contracts, re-run the path and symbol searches, and resolve any ADR number collision. Build from the merged manifests. Versions, schema minimums and the starter recipe must refer to that same snapshot.
2. **Create the independent roots.** Ship lab_roles, inventory and the connector. Set new plugin versions to `0.1.0` and new types to schema 1. Install inventory alone and demonstrate a tube of an unrelated record, split portions with distinct IDs/barcodes, finite balances, lot eligibility when lots are installed, and traceable reasoned holds. For a hold run, test an already-held child, an empty descendant set, a retry, a concurrent clear and a held tube's draw/transfer/split. Use one role grant per actual qualification.
3. **Implement sample receipt and testing.** Start pending, require the assigned source and exactly one ledger debit. The current `draws_received` appends multiple receipts, and the current `draw_target` requires an assigned container, its followed source, a fixed quantity and a computed ready field. A direct lot draw may have no followed record. Add a source-only, single-draw form to that core target check, leaving the stricter stability form intact. Check the pending state, source and one-draw limit under the existing locks **before** the debit. Reuse the receipt writer. Test a wrong source, insufficient stock, wrong scan, quarantined/expired lot, direct mass-unit lot, simultaneous submissions and retries. A refusal must leave both records untouched. Sign the analyst's submitted revision, require a different reviewer who did not edit its measurements, and complete the sample on that signed review. Reopening requires a reason and fresh signatures.
4. **Land requests and consumer changes.** Give concrete types disjoint release policies. Preserve two-project intake, side-specific fields, material receipt, notifications, work-item privacy, request scope and release-only visibility including reports. Exercise an unsigned ordinary collaboration, a one-signature research return and a three-person QC return. Try a plain deliverable against each signed-only request. Recheck the production and sequencing training cases. Move equipment, then rebind the other five consumers. Bump each changed plugin's minor version and increment schema versions for changed existing types. Record the actual direct type minimums, including in plate results and equipment tabs.
5. **Rebuild deployment artifacts.** Generate clean plugin migrations in dependency order with `iki plugin makemigrations` and the declared dependency closure.
