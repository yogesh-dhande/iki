A type says who is told when its records change, in Iki and by email, under
[`notifications`](/reference/plugin-spec/entity-type/#notifications): each notification by name,
when it's sent, and whom it tells. Iki decides the rest:

- Each person is told only while they can read the record, and not of their own change. An agent's,
  a run's or a trigger's change made for them does tell them.
- It's sent as each person chooses, folded with others of its kind into one notification and one
  email, and each one sent is in the record's audit log.
- Emails say what happened and link to it, without the record's values.

Each person chooses, per notification, in Iki and by email, in Iki only, or off, everywhere or in
one project, and can watch or mute a record.

The Lots plugin's lots tell whoever made a lot when QA releases it, and when QA puts it on hold or
rejects it, which nobody can turn off:

```yaml
notifications:
  released:
    label: Released
    description: Whoever made a lot hears when QA releases it.
    when: { field: disposition, to: released }
    tell: { fields: [made_by], watchers: true }
    message:
      title: "{{ hrid }} was released"
      body: "QA released lot {{ lot_number or hrid }} for use."
  held:
    label: On hold or rejected
    when: { field: disposition, to: [on_hold, rejected] }
    tell: { fields: [made_by], watchers: true }
    required: true
    message:
      title: "{{ hrid }} is {{ disposition }}"
      body: "Lot {{ lot_number or hrid }} can't be used. Its history says why."
```

## When it's sent

[`when`](/reference/plugin-spec/entity-type/#notifications.when) is one of:

- [`created: true`](/reference/plugin-spec/entity-type/#notifications.when.created): a record is
  made.
- A [`field`](/reference/plugin-spec/entity-type/#notifications.when.field) changing, optionally
  [`to`](/reference/plugin-spec/entity-type/#notifications.when.to) and
  [`from`](/reference/plugin-spec/entity-type/#notifications.when.from) a value or values, for
  state, enum and bool fields (`notification-values`, `unknown-state`). The field can be a
  referenced record's, `ref.field`: every record referring to the one that changed is told of, up
  to 1000.
- For a [request type](/guides/write-a-plugin/requests/),
  [`sent: true`](/reference/plugin-spec/entity-type/#notifications.when.sent), as the request is
  sent, which tells only `roles`, held in the service's project; or
  [`released: true`](/reference/plugin-spec/entity-type/#notifications.when.released), as each of
  its results is released back, which tells whom it names in the project that asked, if they can
  read both the request and the result.

[`where`](/reference/plugin-spec/entity-type/#notifications.where) keeps only the records a search's
conditions find, on the type's own fields, as a component's search takes them; `{{ now }}` is the
moment it's sent, for date and datetime fields (`notification-where`). The Equipment plugin's
bookings tell whoever a booking is for, and whoever booked it, when its instrument goes out of
service, if the booking hasn't ended or been cancelled:

```yaml
notifications:
  instrument_down:
    label: Instrument out of service
    when: { field: instrument.service, to: out_of_service }
    where:
      all:
        - { field: ends_at, op: gte, value: "{{ now }}" }
        - { field: cancelled, op: eq, value: false }
    tell: { fields: [booked_by], creator: true }
    message:
      title: "{{ instrument }} is out of service"
      body: "The booking “{{ purpose }}” starts {{ starts_at }}."
```

## Whom it tells

[`tell`](/reference/plugin-spec/entity-type/#notifications.tell) names at least one of
(`notification-recipients`):

- [`fields`](/reference/plugin-spec/entity-type/#notifications.tell.fields): the type's
  [person fields](/guides/write-a-plugin/people/);
- [`roles`](/reference/plugin-spec/entity-type/#notifications.tell.roles): lab roles whose holders
  in the record's project are told (`unknown-role`);
- [`creator`](/reference/plugin-spec/entity-type/#notifications.tell.creator): whoever made the
  record;
- [`watchers`](/reference/plugin-spec/entity-type/#notifications.tell.watchers): those who watch it;
- [`actor`](/reference/plugin-spec/entity-type/#notifications.tell.actor): the person who made the
  change, who isn't told otherwise.

A notification that tells an assignment field's person when the record becomes theirs repeats
Iki's own "It's ready for you" (`notification-repeats-ready`, a warning).

## Its message

[`message`](/reference/plugin-spec/entity-type/#notifications.message) has a
[`title`](/reference/plugin-spec/entity-type/#notifications.message.title), up to 200 characters,
and a [`body`](/reference/plugin-spec/entity-type/#notifications.message.body), up to 1000, in the
display title's template language: field names, `hrid`, strings and `or`
(`notification-message`). States show their label, people their name, and references their HRID
only to someone who can read them. Without a message it reads "SAM-000012: Sample ready for review".

## Email and notifications nobody can turn off

- [`email: false`](/reference/plugin-spec/entity-type/#notifications.email) sends it in Iki only,
  unless someone chooses email too.
- [`required: true`](/reference/plugin-spec/entity-type/#notifications.required) means nobody can
  turn it off in Iki, or mute it on a record; whether it's emailed stays their choice.

## Subtypes and registry fields

A type's notifications are its parents' too, and can't reuse a parent's names
(`notification-shadows-parent`). A registry entry's fields can't send one, since an entry has no
project to tell (`notification-in-registry`).
