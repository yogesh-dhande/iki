## In short

Many cores are one person. Nadia Rahman runs whole-plasmid sequencing on a nanopore sequencer for
the institute's research projects: she takes each request, runs it, and sends back the results.
In Iki each step of a request is set by a lab role, so she holds all three that the Plain request
and Plain deliverable use, in the core's project:

- **Coordinator**, to accept or decline requests and receive their tubes;
- **Analyst**, to set a request In progress, and to be named its analyst;
- **Reviewer**, to deliver each result and close the request.

Plain requests and deliverables take no signatures and don't ask for a second person, so one
person can take every step. Every step is still a revision that names her.

## Setting up the core

As the project's Admin, Nadia does three things once, in the core's project settings:

1. Chooses what it takes: Plain requests, from the projects she serves.
2. Allows its records to be shared with other projects. Without it, results can't go back.
3. Gives herself the lab roles Coordinator, Analyst and Reviewer. Lab roles are given in each
   project, so these hold only in the core's.

A project role, Admin included, never sets a state by itself: each state takes its lab role.

## When one person isn't enough

Some labs' procedures need a second person to check a result before it goes back. Plain types
don't ask for one. The [QC request](/reference/plugins/requests/#QCRequest) and
[QC deliverable](/reference/plugins/requests/#QCDeliverable) do: the analyst signs the deliverable
Submitted, a reviewer who didn't create, submit or edit it signs it Reviewed, and QA, someone else
again, signs it Released. A one-person core can't release a QC deliverable alone. With more than
one person, see [Schedule a core's work across several people](/use-cases/schedule-a-cores-work-across-several-people/).
