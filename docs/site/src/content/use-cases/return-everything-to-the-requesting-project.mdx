## In short

The simplest way to run a core: everything it records about a request goes to the project that
asked. The core writes two kinds of thing, and the requester reads both:

- **Its fields on the request**: its status, priority, scheduled date, analyst and service notes.
  The requester reads them on the request as the core sets them, and can't change them.
- **A result for each tube**, a Plain deliverable. Each is the core's until a Reviewer delivers it,
  and Iki won't let the request close while one it recorded hasn't gone back.

The core keeps no work items, notes or files of its own for the request. When it needs those, see
[Keep a core's working records private](/use-cases/keep-a-cores-working-records-private/).

## What Iki checks

- A sequencing request names its method and at least one tube, or it can't be saved.
- A deliverable names a tube on the request, or an aliquot the core split from one, and a
  successful one has its sequencing files or a public read archive accession.
- A deliverable is delivered only while the request is open and in progress.
- The request is set Delivered only once each of its tubes has a delivered result and every
  deliverable recorded for it has been delivered. After that, no deliverable can be added.

Each of these changes is a revision of its record: see
[What Iki keeps of every record](/concepts/what-iki-keeps-of-every-record/).
