<Layer n={1} id="short" title="In short">
  <p class="lead">A plasmid prep is a tube of plasmid DNA made from a plasmid your lab has registered. A <strong>verification</strong> records whether the tube holds that plasmid: Iki compares the prep's sequencing with the plasmid's registered sequence, and a reviewer records the outcome and signs it.</p>
  <ul>
    <li>The comparison is computed once from the sequencing, and can't be edited.</li>
    <li>The outcome is the reviewer's: a match, a discrepancy or inconclusive, with notes and signatures.</li>
    <li>Releasing the lot the prep belongs to is a separate step.</li>
  </ul>
</Layer>

alignment is computed by Iki on one of the lab's workers. The verification is the reviewer's.

<Layer n={4} id="rules" title="The rules in full">
<Rules>
<Rule id="checked" summary="What a verification checks against" open>

A verification is about one prep and the plasmid it should hold. It records the plasmid's
sequence exactly as it was when the check ran, so a later edit to the plasmid doesn't change what
the verification says.

The evidence is an alignment of the prep's reads, a report from elsewhere, or both. An alignment
is always against the plasmid's own registered DNA sequence. For a report, the reviewer confirms
that it belongs to this prep and this plasmid.

</Rule>
<Rule id="agreement" summary="Matches, differs, incomplete">

The alignment's agreement is computed, and is one of three values:

- **matches**: every base is called and agrees with the plasmid's sequence.
- **differs**: at least one difference.
- **incomplete**: nothing differs, but some bases aren't called.

A base that the plasmid's sequence allows (an ambiguity code such as R, for A or G) is not a
difference, and neither is an uncalled base (N).

The outcome is the reviewer's: **match**, **discrepancy** or **inconclusive**. A match over an
alignment that differs or is incomplete needs a written reason, which the signatures cover.
Differences can still support a match, with notes on why each one doesn't count against the prep.

</Rule>
<Rule id="naming" summary="How differences are named">

Each difference is named in HGVS, the standard notation for sequence changes: `o.` on a circular
molecule, `g.` on a linear one. Positions count from 1, and an insertion or deletion is placed at
its 3'-most position. For example, `o.887del` is one base deleted at 887.

Each difference also lists the plasmid's features it falls in, the length of the run of one base
it lies in, and, from reads, its depth and the reads that agree with it on each strand.

</Rule>
<Rule id="circle" summary="Reads round a circle, and runs of one base">

A plasmid is a circle, so a read can cross position 1, and so can a difference. Iki aligns each
read with minimap2 across the origin, so such a read counts in one piece, and moves each insertion
or deletion to its 3'-most position, so one deletion in a run of one base counts at one place.

The consensus takes the majority base at each position with at least {v.min_depth} reads (the
default); a position with fewer is N. Iki then aligns the reads to that consensus again until it
stops changing, in at most four rounds ({v.polishing_rounds} here), and compares it with the
plasmid's sequence on either strand, from any starting point.

Nanopore errors cluster in runs of one base, and Iki's majority call can keep such an error at
modest depth, so check the run length on each difference before calling it real; a sequencing
service's polished consensus can be compared instead.

</Rule>
<Rule id="corrections" summary="Corrections and new evidence">

Correcting the outcome, the notes or the reviewer returns the verification to Recorded for a new
review. The earlier signatures stay in its history. New sequencing is a new verification of the
same prep, so a prep can have several.

In Regulated QC, the reviewer can't be the person who created, submitted or edited the
verification, and QA must be someone else again.

</Rule>
</Rules>
